# 5. Time-Series Databases and the Alternatives — brief and source ledger

## Brief

- **Hook.** Three databases answered the same question -- the last quote before each of a million trades -- in times a hundred-fold apart, and the slowest was the one built for time series: the query's shape, not the product's category, decided the winner.
- **Sections.** What a time-series database promises; Query shapes of market data; In-process engines against servers; A benchmark that means something; A survey of the field.
- **Defines.** time-series database, embedded database, vectorised query execution, late materialisation, downsampling, time bucket.
- **Uses (defined earlier).** tick store (ch4), as-of join (B7.3), columnar layout (ch3), predicate pushdown (ch3), memory-mapped file (ch4), microbenchmark (B13.2), bar (B7.2).
- **Tutorial.** Run one benchmark suite -- point lookup, time-range scan, bar aggregation into time buckets, as-of join, cross-sectional group-by -- on DuckDB, Polars, SQLite, pandas and the flat memory-mapped file, on the same generated day, with warm and cold caches and repeated interleaved runs. End state: a heat-map table of median times by engine and query shape, measured on this laptop.
- **Build.** `firm.tsbench`: query-shape definitions, engine adapters with identical results checked before any timing, interleaved repetitions, cold/warm protocol, report with medians and spreads; Python.
- **Weekend problem.** The right tool for each question -- named result: the engine-by-query-shape latency matrix on this laptop, the winner of each shape, and the query mix at which an embedded columnar engine beats a row store for a research workload.
- **Facts to verify.** kdb+/q product documentation (licence model, columnar in-memory design): one survey row, sourced; ClickHouse, QuestDB, TimescaleDB, InfluxDB and ArcticDB documentation: storage model and licence (dated survey table); Boncz, Zukowski and Nes 2005, MonetDB/X100: hyper-pipelining query execution (CIDR); Raasveldt and Muehleisen 2019, DuckDB: an embeddable analytical database (SIGMOD demo).
- **Data.** The chapter 4 store's generated day.
