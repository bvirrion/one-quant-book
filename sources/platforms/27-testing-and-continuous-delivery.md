# 27. Testing and Continuous Delivery — brief and source ledger

## Brief

- **Hook.** On 1 August 2012 a broker-dealer deployed new order-routing code to seven of its eight servers; the eighth ran a retired function that the release had repurposed a flag for, and in about forty-five minutes the firm sent millions of orders and lost more than four hundred million dollars.
- **Sections.** The test pyramid for trading code; Golden files for pricers; Continuous integration; Release trains and change control; Deploying and rolling back.
- **Defines.** test pyramid, unit test, integration test, end-to-end test, golden-file test, continuous integration, continuous delivery, deployment pipeline, release train, change control, blue--green deployment, rollback.
- **Uses (defined earlier).** property-based test (B13.25), differential test (B13.25), fuzz testing (B13.25), performance regression gate (B13.25), exchange certification (B13.25), canary deployment (B7.21), staged rollout (B7.21), reference pricer (B5.28), model validation (B6.26), Monte Carlo method (B4.26), feature flag (ch16), configuration drift (ch16), parity harness (ch12).
- **Tutorial.** Freeze golden values of Book 5's pricing library over a portfolio, with tolerances derived from each engine's own error (Monte Carlo standard errors, grid convergence), and run the golden-file test against planted changes (a sign error, a day-count change, a Monte Carlo seed change, a genuine model improvement); tune the tolerance between false alarms and misses; wire the test tiers into a deployment pipeline with a release train and a deployment check that every server runs the same build and configuration. End state: detection and false-alarm rates against tolerance, and the pipeline's stage times.
- **Build.** `firm.goldtest`: golden-value store (values, tolerances, provenance, approval of updates), comparison with per-engine tolerances and a change-impact report, a test-tier runner with timings, a release-train simulator, and a deployment consistency check (build hash and configuration hash per host); Python.
- **Weekend problem.** Seven of eight servers -- named result: the detection rate of each planted regression and the false-alarm rate of Monte Carlo noise at each tolerance, the tolerance that minimises expected cost, and the consistency check that would have refused the partial deployment.
- **Facts to verify.** SEC order In the Matter of Knight Capital Americas LLC (2013), Release 34-70694: deployment to seven of eight servers, repurposed flag, 45 minutes, loss over $460 million; JPMorgan Chase Management Task Force report on CIO losses (2013): spreadsheet-based model errors; Humble and Farley 2010, Continuous Delivery; Cohn 2009, Succeeding with Agile (test pyramid); Commission Delegated Regulation (EU) 2017/589 (RTS 6) testing and change management (articles 5-7, dated).
- **Data.** Book 5's firm.pricing and synthetic portfolios.
