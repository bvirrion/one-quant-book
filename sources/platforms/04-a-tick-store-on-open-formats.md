# 4. A Tick Store on Open Formats — brief and source ledger

## Brief

- **Hook.** At 16:05 the day's capture files close; by 16:40 they must be compacted, sorted and queryable, because the overnight research runs start at 17:00, and a researcher who asks for yesterday's quotes as of each of today's trades must not notice which of the two stores answered.
- **Sections.** Live capture: append-only files; End-of-day compaction; The intraday and the historical store; As-of joins at scale; Flat files and memory mapping; Schema evolution.
- **Defines.** tick store, intraday store, historical store, end-of-day compaction, append-only file, sort key, flat file format, memory-mapped file, schema evolution, schema version.
- **Uses (defined earlier).** point-in-time data (B7.3), valid time (B7.3), knowledge time (B7.3), bitemporal data (B7.3), as-of join (B7.3), memory-mapped dataset (B12.23), page fault (B13.6), huge page (B13.3), partition key (ch2), row group (ch3), zone map (ch3), predicate pushdown (ch3), columnar layout (ch3).
- **Tutorial.** Capture a simulated session from firm.exchsim live into two intraday forms (fixed-width flat records and an Arrow IPC stream), compact at the close into Parquet partitioned by date and symbol and sorted by time, then answer one query through a single interface over both stores in DuckDB; run the same trade-to-quote as-of join in DuckDB, in Polars and with firm.pit's reference join and check they agree row for row; map the flat file with numpy.memmap and with a C++20 mmap reader; add a column to the schema and read old and new files together. End state: the as-of join's agreement, a table of query time and bytes read by store, and the compaction's size and time.
- **Build.** `firm.tickstore`: intraday writer (flat records with a versioned header, Arrow IPC), compactor (sort, partition, row-group sizing, footer statistics), query layer (one API over intraday and historical, DuckDB underneath), as-of join helpers for DuckDB and Polars checked against firm.pit, schema registry with evolution rules; C++20 and Rust readers of the flat format through mmap; Python.
- **Weekend problem.** The 16:40 deadline -- named result: the compaction time and output size per million messages, the query latency on each store for a one-symbol hour and a full-universe as-of join, and the largest day the 35-minute window can absorb at the measured rate.
- **Facts to verify.** kdb+ as the long-standing proprietary tick-database standard in banks and trading firms (one sourced remark: vendor documentation or a public talk); DuckDB ASOF JOIN documentation; Polars join_asof documentation; Apache Arrow IPC streaming and file format specification; Linux mmap(2) and madvise(2) manual pages.
- **Data.** firm.exchsim session generated by script (tests use seconds; the chapter's day is generated once, late).
