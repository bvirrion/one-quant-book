# 11. Backtest-Engine Architecture — brief and source ledger

## Brief

- **Hook.** A quoting strategy made money at the first three fidelity levels and lost it at the fourth, where its own orders became part of the market it traded against; the firm had four backtesters written by four teams, and it took a week to be sure the difference was the market and not the code.
- **Sections.** One engine, four levels; The event model and the clock; Data access; The results store; Adding a level: the reactive simulation.
- **Defines.** backtest engine, event model, data-access layer, results store, reactive simulation.
- **Uses (defined earlier).** backtest (B7.16), fidelity level (B7.16), vectorised backtest (B7.16), event-driven backtest (B7.17), simulated clock (B7.17), fill model (B7.17), order-book replay (B7.18), queue-position model (B7.18), latency model (B7.18), sim-to-live reconciliation (B7.19), paper trading (B7.21), exchange simulator (B10.26), event loop (B13.20), injected clock (B13.20), tick store (ch4), data snapshot (B7.29).
- **Tutorial.** Wrap Book 7's three backtesters (firm.vecbt, firm.evbt, firm.lobreplay) and Book 10's exchange simulator behind one engine: one strategy interface, one event model, one clock, one data-access layer reading the tick store, one results store; run one quoting strategy on replay and on the simulator with Book 10's ReplayStrategyAdapter, and a daily portfolio strategy at level 1 and 2, recording every run with its data snapshot and code hash. End state: the P&L ladder of one strategy across the levels and the reactive level's gap, as a figure.
- **Build.** `firm.btengine`: `Engine(level, strategy, data, config).run() -> Run` for levels 1-3 (Book 7's backtesters, unchanged) and the reactive level on firm.exchsim; `Strategy` protocol and adapters; event model with total ordering (time, class, sequence); data-access layer over firm.tickstore; results store (Parquet plus a JSON manifest: level, data snapshot hashes, code hash, parameters, seed) with a query API; Python.
- **Weekend problem.** Four backtesters, one strategy -- named result: the quoting strategy's P&L an hour at each level with standard errors over seeds, and the share of the gap between replay and reactive simulation explained by fills that exist only because the strategy was in the book.
- **Facts to verify.** Book 7's level definitions and the reactive stand-in (prose pointer, no ledger row needed); a public description of an industrial backtest-engine architecture (open-source engine documentation, e.g. an event-driven framework, dated).
- **Data.** firm.exchsim with TapeBackground and firm.agentmkt populations; generated by script.
