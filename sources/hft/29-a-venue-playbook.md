# 29. A Venue Playbook — brief and source ledger

## Brief

- **Hook.** The same quoting code behaves differently on a price-time equities exchange, a pro-rata futures book, a venue with a speed bump and a crypto exchange with a request budget; a desk keeps one page per venue so that nobody learns the differences in production.
- **Sections.** What a venue profile holds; Equities and options venues; Futures and FX venues; Crypto, on-chain and event venues; Onboarding a new venue.
- **Defines.** venue profile.
- **Uses (defined earlier).** price-time priority (B1.19), pro-rata allocation (B1.19), maker-taker pricing (B1.9), speed bump (ch9), frequent batch auction (ch9), rate limit (B3.15), market-by-order (B1.19), market-by-price (B1.19), last look (B2.15), on-chain order book (B3.21).
- **Tutorial.** Encode venue profiles for eight venue types (matching rule, fees, feed, order types, limits, quirks) and run one quoting strategy through firm.mmharness on each configuration to show which parameters must change.
- **Build.** `firm.venueprofile`: a venue-profile schema and registry with validation, and the harness configuration it produces for each venue type; Python, on firm.venues and firm.feesched.
- **Weekend problem.** One code, eight venues — named result: the quoting strategy's capture and message count on each venue type with and without the venue-specific parameters.
- **Facts to verify.** Matching rules, fees and feed types of one venue per type (CME, Nasdaq, Cboe, IEX, Eurex, EBS or LSEG FX, a major crypto venue, a betting exchange or Kalshi) (dated).
