# 14. Vector Instructions and Data-Parallel Code — brief and source ledger

## Brief

- **Hook.** A parser that reads one byte at a time looks at a JSON message the way a person reads a page letter by letter; a published parser that reads thirty-two bytes per instruction processes gigabytes a second on one core.
- **Sections.** SIMD registers and instruction sets; Auto-vectorisation and what blocks it; Intrinsics and CPU feature dispatch; Where vectorisation pays in a trading system; Structure of arrays.
- **Defines.** SIMD, vector instruction, auto-vectorisation, compiler intrinsic, CPU feature dispatch, structure of arrays.
- **Uses (defined earlier).** instructions per cycle (ch2), compiler barrier (ch2), function multiversioning (ch8), fused multiply-add (B4.25).
- **Tutorial.** Find a delimiter and parse eight ASCII digits with AVX2 intrinsics behind a runtime feature check, with a scalar reference that the tests compare byte for byte; price a batch of options stored as a structure of arrays and read the compiler's vectorisation report at -O2 and -O3 under g++ 11; the same scan in Rust with std::arch. End state: bytes per cycle of the scalar, SSE and AVX2 scans by message length, measured on this laptop.
- **Build.** `firm.simdscan`: byte-class scanning (delimiters, structural characters) and integer and fixed-point parsing, with scalar fallbacks and dispatch; C++20 and Rust. Consumed by firm.fixengine and firm.wsclient.
- **Weekend problem.** Thirty-two bytes at a time -- named result: the message length below which the vector scan does not repay its setup, from the measured cost per byte and per call.
- **Data.** Measured on this laptop only.
- **Facts to verify.** Langdale and Lemire 2019, Parsing gigabytes of JSON per second (VLDB Journal); Lemire 2021, Number parsing at a gigabyte per second (Software: Practice and Experience); Intel Intrinsics Guide (AVX2); GCC 12 release notes: vectorisation enabled at -O2 (so not in g++ 11).
