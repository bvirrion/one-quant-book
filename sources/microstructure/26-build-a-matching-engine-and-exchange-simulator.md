# 26. Build: a Matching Engine and Exchange Simulator — brief and source ledger

## Brief

- **Hook.** Every tutorial in the books that follow needs a venue: something that accepts orders, matches them, publishes what happened in a feed that can drop packets, and does exactly the same thing every time it is run with the same inputs.
- **Sections.** What an exchange does, in messages; The matching engine; The market-data feed: sequencing, redundancy, recovery; The order-entry protocol and its sessions; Clock, latency and determinism.
- **Defines.** exchange simulator, order-entry protocol, order-entry session, execution report, self-trade prevention, cancel on disconnect, redundant feed lines, snapshot recovery, retransmission request.
- **Uses (defined earlier).** matching engine (ch1), limit order book (ch1), order-book event (ch1), time in force (ch2), iceberg order (ch2), pegged order (ch2), price-time priority (B1.19), pro-rata allocation (B1.19), top-order allocation (B1.19), market-by-order (B1.19), sequence number (B1.28), exchange timestamp (B1.28), receive timestamp (B1.28), market data feed (B1.4), order lifecycle (B7.17), simulated clock (B7.17), latency model (B7.18), order-entry latency (B7.18), market-data latency (B7.18), order-book replay (B7.18), call auction (B1.13), uncrossing price (B1.13), trading pause (ch25), rate limit (B3.15), snapshot-and-delta feed (B3.26), book checksum (B3.26), counter-based generator (B4.26), feed handler (B13.18, forward), line arbitration (B13.16, forward).
- **Tutorial.** Start firm.exchsim in process, connect a Python client through the byte-stream transport, send orders and read the execution reports; drop packets on line A and recover from line B, then from a snapshot; run the same inputs through the C++20 and Rust engines and check byte-identical feeds; start the C++20 server on localhost and trade on it from Python; measure throughput on this laptop. Data: none (deterministic scenarios and the tape's background flow).
- **Build.** `firm.exchsim`: the exchange simulator -- matching engine (on firm.lob and firm.ordertypes, allocation by Book 1's firm.match), trading phases and auctions (firm.auctionsim), halts (firm.halts), fees, sequenced binary market-data feed (superset of Book 1's firm.feed layout) on two redundant lines with snapshot and retransmission channels, binary order-entry protocol with sessions, throttles, self-trade prevention and cancel-on-disconnect, deterministic clock and latency model, multi-venue harness, tape export for Book 7's tools; Python reference, C++20 engine, codecs and localhost server, Rust engine and codecs; acceptance tests: conformance scenarios, three-language byte-identity on a fixture, determinism by hash, recovery under packet loss.
- **Weekend problem.** Certification day -- named result: the conformance suite passed by each engine, the byte-identity of the three engines' feeds on the fixture, and the engines' messages per second measured on this laptop.
- **Facts to verify.** Nasdaq TotalView-ITCH 5.0 specification (message layouts, sequencing via MoldUDP64); Nasdaq OUCH order-entry specification (dated); Nasdaq MoldUDP64 and SoupBinTCP specifications; CME MDP 3.0: A and B feeds, snapshot recovery, packet sequence numbers (dated; via the client-systems wiki); CME iLink 3 / self-match prevention and cancel on disconnect functionality (dated); FIX Trading Community Simple Binary Encoding standard; LSEG / Cboe binary order-entry specifications for comparison (dated).
