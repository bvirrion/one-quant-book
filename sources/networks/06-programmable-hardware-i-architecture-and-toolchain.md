# 6. Programmable Hardware I: Architecture and Toolchain — brief and source ledger

## Brief

- **Hook.** A 10 Gb/s Ethernet port delivers its bytes to a gate array 64 bits at a time at about 156 million words a second; a design that takes one word per clock cycle has seen a 64-byte frame after eight cycles, and it takes exactly that long every time. Determinism, not raw speed, is what programmable hardware sells.
- **Sections.** The fabric: logic blocks, memories, transceivers and clocks; Describing hardware: register-transfer level and high-level synthesis; Timing closure: clock periods, critical paths and pipelining; Simulation and verification; Smart network cards.
- **Defines.** field-programmable gate array, configurable logic block, block RAM, register-transfer level, hardware description language, logic synthesis, place and route, high-level synthesis, timing closure, critical path, clock domain crossing, testbench, cycle-accurate model, SmartNIC.
- **Uses (defined earlier).** network interface card (ch1), Ethernet frame (ch1), line rate (ch1), instruction pipeline (B13.2), PCI Express (B13.4), direct memory access (B13.4), hot path (B13.1), latency (B13.1), property-based test (B13.25).
- **Tutorial.** Write a first SystemVerilog design, a streaming field extractor on a 64-bit valid/ready byte-stream interface (it pulls a big-endian field out of each frame on the fly), simulate it under Verilator 4.038 with a C++ testbench and under Icarus Verilog 11 with a SystemVerilog testbench, and compare every output with a Python golden model; then pipeline its comparator and count the cycles added against the logic levels removed. End state: a cycle-by-cycle table of the first frame, green comparisons in both simulators, and a chart of latency in nanoseconds against pipeline depth at three clock frequencies.
- **Build.** `firm.hdlkit`: the book's hardware toolkit -- SystemVerilog stream primitives (valid/ready interface, skid buffer, big-endian field extractor, CRC-32 unit, cycle counter), pytest drivers that build and run a design under Verilator (--cc --exe --build) and Icarus, a golden-model comparator, and a C++20 cycle-model base class; acceptance: every primitive matches its Python model on random streams with random back-pressure in both simulators; the tests fail if a simulator is missing. Consumed by chapter 7.
- **Weekend problem.** Eight cycles -- named result: the pipeline depth that meets a target clock for a decision of a given number of logic levels, and the resulting decision latency in nanoseconds, against the unpipelined design at its own maximum clock.
- **Facts to verify.** IEEE 802.3 clause 49 (10GBASE-R): 64b/66b coding, 156.25 MHz reference / 10.3125 Gb/s line rate; AMD (Xilinx) UltraScale+ architecture guides: six-input LUT, CLB, 36 Kb block RAM, transceivers (dated); Intel (Altera) Agilex fabric overview (dated); IEEE 1800-2017 (SystemVerilog); Verilator 4.038 and Icarus Verilog 11 documentation; AMD Vitis HLS user guide: initiation interval and pipelining pragmas; Lockwood, Gupte, Mehta, Blott, English, Vissers 2012, 'A low-latency library in FPGA hardware for high-frequency trading' (IEEE Hot Interconnects); a named SmartNIC or FPGA network card and its published port-to-port latency (dated).
- **Data.** Simulated only (Verilator, Icarus); no FPGA toolchain or hardware.
