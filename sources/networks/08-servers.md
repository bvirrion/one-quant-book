# 8. Servers — brief and source ledger

## Brief

- **Hook.** The servers that trading firms buy for the hot path are chosen for one core's speed, not for the number of cores: specialist vendors sell machines with a handful of cores clocked well above the processor maker's rating, cooled by liquid, warranted by the vendor rather than by the chip maker.
- **Sections.** Choosing the processor; Firmware settings; Overclocked and liquid-cooled machines; Memory, reliability and management; Racks, power and heat.
- **Defines.** thermal design power, overclocking, system management interrupt, error-correcting code memory, baseboard management controller, rack unit, burn-in test.
- **Uses (defined earlier).** dynamic frequency scaling (B13.2), idle state (B13.2), simultaneous multithreading (B13.2), instructions per cycle (B13.2), cache miss (B13.3), non-uniform memory access (B13.4), core isolation (B13.13), tickless kernel (B13.13), hot path (B13.1), microbenchmark (B13.2), device locality (B13.4).
- **Tutorial.** Fit a two-part latency model, t = cycles / f + memory time, to Book 13's microbenchmarks rerun on this laptop's performance and efficiency cores at their different clocks; evaluate it for a core-bound and a memory-bound tick-to-trade path on a table of candidate server processors (base and turbo frequency, cache, cores, thermal design power: dated, ledger rows); add the power each draws against a colocation cabinet's kilowatt budget. End state: a chart of predicted path latency against clock frequency for both paths, and a ranking table of candidate machines per cabinet.
- **Build.** `firm.serverspec`: candidate machines as data (processor, frequencies, cache, cores, memory channels, thermal design power, rack units, source row), the latency model and its fit, a ranking by path latency under a per-cabinet power and space budget, and a firmware-settings checklist as data that extends firm.tuneaudit's audit (wrapped, not edited); Python. Consumed by chapters 9 and 29.
- **Weekend problem.** Five gigahertz or fifty cores -- named result: the speed-up of a tick-to-trade path on an overclocked part against a standard server part, given the path's split between core-bound and memory-bound time, and how many of each fit in a cabinet's power budget.
- **Facts to verify.** Intel and AMD processor specification pages for named server parts: base and turbo frequency, cache, TDP (dated); a specialist overclocked-server vendor's published specification (dated); Intel definition of thermal design power; a vendor or Red Hat low-latency BIOS tuning guide (C-states, P-states, SMIs, SMT); Intel SDM on system management mode and SMIs; DMTF Redfish / IPMI documentation for baseboard management controllers; EIA-310 rack unit (1.75 in).
- **Data.** Candidate machine table from vendor pages (dated ledger rows); laptop microbenchmarks (measured, caption names the machine).
