# 16. Trading in a Public Cloud — brief and source ledger

## Brief

- **Hook.** In one cloud provider's documentation the zone called 'us-east-1a' in one account is not necessarily the zone called 'us-east-1a' in another: names are shuffled per account, and only the zone identifier says where the machines are. Two firms that agree to meet in 'zone a' may be kilometres apart.
- **Sections.** Regions, availability zones and zone identifiers; Placement groups and instance selection; Network adapters, virtualisation and bare metal; Jitter and noisy neighbours; Clocks and costs in the cloud.
- **Defines.** public cloud, availability zone, availability-zone identifier, placement group, bare-metal instance, single-root I/O virtualisation, CPU steal time, noisy neighbour, data-transfer charge.
- **Uses (defined earlier).** cloud region (B3.26), jitter (B13.1), tail latency (B13.1), kernel bypass (B13.13), Precision Time Protocol (ch4), clock offset (ch4), network interface card (ch1).
- **Tutorial.** A labelled simulation with parameters from cited documentation: round-trip times within a placement group, within a zone and across zones, a noisy-neighbour mixture on shared instances against bare metal, and the probability that two accounts' same-named zone is the same physical zone; then a monthly cost table for three instance plans from dated list prices. End state: simulated RTT distributions by placement and a cost table.
- **Build.** `firm.cloudplan`: region and zone model, a zone-name to zone-identifier resolver reading a describe-availability-zones response (a fixture in the provider's documented shape, synthetic values), an instance catalogue as data (dated rows), a placement plan and its monthly cost including data transfer; Python. Consumed by chapters 17-19 and 29.
- **Weekend problem.** us-east-1a is not your us-east-1a -- named result: the probability that two accounts' same-named zone is the same physical zone when names are shuffled over n zones, and the expected round-trip penalty of trusting names instead of identifiers.
- **Facts to verify.** AWS documentation: availability-zone IDs and per-account name mapping; AWS documentation: placement groups (cluster, partition, spread); AWS documentation: Elastic Network Adapter, ENA Express, bare-metal instances (dated); Amazon Time Sync Service and its PTP hardware clock accuracy claim (dated); Azure proximity placement groups and Google Cloud compact placement policies (dated); cloud on-demand and data-transfer list prices (dated); a published measurement study of cloud network latency or jitter (paper).
- **Data.** Provider documentation (dated ledger rows); simulations labelled; no cloud account.
