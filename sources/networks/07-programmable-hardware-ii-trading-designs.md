# 7. Programmable Hardware II: Trading Designs — brief and source ledger

## Brief

- **Hook.** The design has decided whether to send an order before the last byte of the packet that triggered it has arrived: the price field sits in the first sixty bytes, and waiting for the frame's checksum would cost more cycles than the whole decision.
- **Sections.** Feed decoding in hardware; Book building in hardware; Risk checks in cycles; Order generation from templates; Hybrid designs: what stays in software and why.
- **Defines.** hybrid trading system, hardware trigger, order template, cut-through decision, register map, TCP offload engine.
- **Uses (defined earlier).** field-programmable gate array (ch6), cycle-accurate model (ch6), testbench (ch6), timing closure (ch6), pre-trade risk check (B11.27), kill switch (B11.27), market access rule (B11.27), risk gate (B13.22), token bucket (B13.21), order-entry protocol (B10.26), feed handler (B13.18), book builder (B13.19), latency race (B11.9), tick-to-trade latency (B13.1), fail-closed design (B13.22).
- **Tutorial.** Build a hardware trigger for one instrument of Book 10's simulator: a MoldUDP64 and message parser (add, execute, delete), a top-of-book tracker, a trigger rule whose threshold software writes into a register map, a risk stage (maximum size, a token-bucket order rate, a kill bit) and an order template whose price, quantity and client order id are patched in flight; simulate it under Verilator and Icarus on a recorded simulator session and check its orders against a C++20 cycle model and a Python golden model. End state: identical orders in all four, a histogram of cycles from the triggering byte to the first order byte, and the same path's latency in software from Book 13.
- **Build.** `firm.hwtrade`: the design (SystemVerilog, on firm.hdlkit), its C++20 cycle model and its Python golden model; acceptance: identical orders on the recorded fixture in Verilator, Icarus, C++ and Python; a bounded number of cycles from trigger to first order byte; every risk check at its boundaries; the kill bit stops all output within a stated number of cycles. firm.wirepath gains a hardware-path variant for chapter 29.
- **Weekend problem.** The trigger that must not fire twice -- named result: the latency of the hybrid path in nanoseconds against Book 13's software path, the probability of winning a race against one competitor at each (Book 13 ch. 1's race model), and the most orders the token bucket lets out in a burst before software can pull the kill bit.
- **Facts to verify.** Lockwood et al. 2012 (Hot Interconnects): feed-processing latency in hardware; a named vendor's public figure for hardware tick-to-trade (dated); SEC Rule 15c3-5: controls under the broker's direct and exclusive control (pointer B11.27); a public source describing hybrid FPGA/software trading architectures (paper or conference talk); TCP offload in FPGA: a published paper or vendor document.
- **Data.** Book 10's simulator session (regenerated by script); simulated only.
