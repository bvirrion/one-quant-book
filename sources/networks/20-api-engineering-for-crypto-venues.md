# 20. API Engineering for Crypto Venues — brief and source ledger

## Brief

- **Hook.** A market maker quoting four hundred instruments on one venue cannot put all their depth streams on one connection: the venue caps streams per connection, connections per address and messages per second, and one gap on an overloaded connection forces a resynchronisation of every book it carries.
- **Sections.** Websocket sharding; Snapshots, deltas and sequence gaps at scale; Rate-limit governors across keys and addresses; Choosing among order-entry paths; Redundant connections and which timestamps to trust.
- **Defines.** connection sharding, per-symbol resynchronisation, order-entry path, venue clock skew.
- **Uses (defined earlier).** WebSocket (B13.17), WebSocket frame (B13.17), REST interface (B13.17), FIX session (B13.15), snapshot-and-delta feed (B3.26), book checksum (B3.26), rate limit (B3.15), request weight (B3.15), API key (B3.15), sub-account (B3.15), exchange timestamp (B1.28), receive timestamp (B1.28), clock offset (ch4), message gap (B13.16), connection pool (B13.17).
- **Tutorial.** Plan the shards for a subscription set under a venue's documented limits; run a sharded feed manager on synthetic depth streams with injected gaps, using Book 13's firm.wsclient and Book 3's firm.wsbook, and compare per-symbol with per-connection resynchronisation; allocate one rate budget across three strategies with Book 3's firm.ratelimit; estimate a venue's clock skew from event and receive timestamps with a minimum-delay filter. End state: resynchronisation counts and book-staleness by design, and the skew estimate over time.
- **Build.** `firm.cryptofeed`: a shard planner (streams to connections to addresses under per-connection, per-address and per-second limits as dated data), a per-symbol resynchronisation manager on firm.wsbook, a rate-budget allocator across strategies on firm.ratelimit (wrapped), and a venue clock-skew estimator; Python. Consumed by chapter 29.
- **Weekend problem.** Four hundred symbols, five connections -- named result: the minimum connections and addresses for a subscription set under a venue's limits, and the book-staleness a gap costs with per-symbol against per-connection resynchronisation.
- **Facts to verify.** venues' API documentation: streams per connection, connections per address per interval, message limits, order-entry options (Binance, OKX, Bybit, Coinbase, Kraken, Deribit) (dated box); venues' documentation of timestamp fields (event time, transaction time); RFC 6455 (WebSocket) ping and close; Book 3's and Book 13's components' documented behaviour (pointers).
- **Data.** Synthetic streams in documented shapes; limits as dated rows.
