# 3. Network Cards and Kernel Bypass — brief and source ledger

## Brief

- **Hook.** Between the wire and a UDP socket's recv() call a packet is copied by the card into memory, announced by an interrupt, processed by the kernel's softirq, queued on the socket and copied again: most of the microseconds of a kernel receive are spent on work that a trading process does not need.
- **Sections.** The path of a packet through the kernel; Interrupts, coalescing and receive-side scaling; Polling drivers and user-space stacks; Zero copy and the transmit side; Timestamps on the card.
- **Defines.** descriptor ring, interrupt coalescing, receive-side scaling, flow steering, poll-mode driver, user-space network stack, zero-copy networking.
- **Uses (defined earlier).** network interface card (ch1), Ethernet frame (ch1), kernel bypass (B13.13), busy polling (B13.13), interrupt affinity (B13.13), core isolation (B13.13), direct memory access (B13.4), PCI Express (B13.4), direct cache access (B13.4), device locality (B13.4), hardware timestamp (B13.5), receive buffer overrun (B13.18), context switch (B13.13), ring buffer (B13.12).
- **Tutorial.** Measure on this laptop what the kernel path costs: UDP receive over loopback with blocking recv, non-blocking polling and recvmmsg batching, with software receive timestamps (SO_TIMESTAMPING) splitting kernel time from application time; then run a C++20 model of a card's receive descriptor ring (ownership bits, head and tail, batched refill) consumed by a poll-mode loop, and a Python model of interrupt coalescing's latency against CPU trade-off. End state: a chart of per-packet latency by receive method (measured, laptop named in the caption) and the coalescing trade-off curve (model).
- **Build.** `firm.nicring`: a receive and transmit descriptor-ring model (fixed ring, ownership bit, doorbell, batch refill, drop on a full ring), a poll-mode receive loop and an interrupt-driven loop with coalescing (packets or microseconds), with counters; C++20 and Rust sharing one fixture, Python model of the latency against CPU trade-off; acceptance: no loss or duplication under random producer and consumer interleavings, drops counted exactly when the ring is full, zero allocations.
- **Weekend problem.** Interrupts or polling -- named result: the mean added latency per packet under a given coalescing setting at a given packet rate, and the rate above which polling a dedicated core costs less CPU than taking interrupts.
- **Facts to verify.** Linux kernel documentation: NAPI, 'Scaling in the Linux Networking Stack' (RSS, RPS, RFS, XPS); Linux kernel documentation: timestamping (SO_TIMESTAMPING flags); DPDK documentation: poll mode driver; Linux kernel documentation: AF_XDP; AMD (Solarflare) Onload and ef_vi documentation (dated); a published kernel-bypass latency figure from a vendor or a paper (dated); ethtool interrupt-coalescing parameters (rx-usecs, rx-frames) documentation.
- **Data.** Measured on this laptop (loopback only; no bypass hardware); models deterministic.
