# 27. The Vendor Map — brief and source ledger

## Brief

- **Hook.** A futures exchange's list of certified independent software vendors runs to dozens of firms, its list of connectivity providers to dozens more: a new trading firm buys most of its stack, and its first map of the market is a map of vendors.
- **Sections.** Market data; Execution software and order management; Network hardware and servers; Timing and monitoring; Reading the map: lock-in, concentration and exit.
- **Defines.** independent software vendor, ticker plant.
- **Uses (defined earlier).** order management system (B10.20), execution management system (B10.20), exchange certification (B13.25), direct feed (B1.9), feed handler (B13.18), capture appliance (ch5), grandmaster clock (ch4), financial extranet (ch15), managed infrastructure (ch15), build against buy (B16.20).
- **Tutorial.** Build the vendor map as data (category, product type, vendors named only from a venue's list or the vendor's own publication, each with a source row and date), attach the firm's stack as a dependency graph, and compute single-vendor concentration and the components whose one vendor failing stops trading. End state: a stack diagram coloured by concentration and a table of single points of vendor failure.
- **Build.** `firm.vendormap`: a vendor inventory schema (category, product, vendor, source row, date), a stack dependency graph, concentration and exit-cost measures, and a bill-of-materials export for chapter 29; Python.
- **Weekend problem.** One vendor too many -- named result: the concentration index of a firm's stack and the list of components whose single vendor's failure halts trading.
- **Facts to verify.** exchanges' published lists of certified independent software vendors and connectivity providers (CME, Eurex, Nasdaq, Cboe) (dated); vendors' own product pages for each category named (dated); a public definition of a ticker plant (vendor or paper).
- **Data.** Vendor rows (dated ledger rows); synthetic firm stack.
