# 26. Power, Commodities and Betting Connectivity — brief and source ledger

## Brief

- **Hook.** Europe's cross-border intraday power market matches orders across a dozen countries through one shared order book, and allocates the interconnectors' capacity with each trade, first come, first served: when capacity is scarce, the last megawatt across a border goes to whoever reaches the book first.
- **Sections.** Intraday power interfaces and the shared order book; Grid-operator scheduling systems; Commodity-exchange connectivity; Betting-exchange interfaces and their data charges.
- **Defines.** shared order book, implicit continuous allocation, transaction charge (renamed at writing from *data-request charge*: the betting exchange read no longer charges for data requests, only for transactions above an hourly threshold).
- **Uses (defined earlier).** intraday market (B3.6), gate closure (B3.6), market coupling (B3.5), bidding zone (B3.5), balancing responsible party (B3.6), schedule nomination (B3.13), betting exchange (B3.27), rate limit (B3.15), order-entry path (ch20).
- **Tutorial.** A labelled simulation: orders from several countries reach the shared order book through local trading systems with different latencies; with scarce interconnector capacity allocated implicitly with each match, measure who gets it by latency; then a betting exchange's data charges for polling against streaming, from its dated published charges. End state: capacity share against latency, and a data-cost comparison.
- **Build.** `firm.powerlink`: an intraday power connectivity model (local trading system, shared order book, capacity check, gate-closure clock, message budgets as dated data) and a betting-exchange data-charge calculator; Python. Consumed by chapter 29.
- **Weekend problem.** The last megawatt across the border -- named result: the probability of obtaining scarce cross-border capacity as a function of latency to the shared order book, and its value per megawatt-hour.
- **Facts to verify.** SIDC (single intraday coupling) documentation: shared order book, capacity management module, implicit continuous allocation (ENTSO-E / NEMO Committee); EPEX SPOT or Nord Pool intraday API documentation and limits (dated); Betfair Exchange API documentation: data request and transaction charges (dated); ICE Futures Europe and LME data-centre or connectivity documentation (dated).
- **Data.** Documentation rows (dated); simulation labelled.
