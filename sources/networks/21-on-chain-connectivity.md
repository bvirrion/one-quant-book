# 21. On-Chain Connectivity — brief and source ledger

## Brief

- **Hook.** A transaction sent to a public node reaches the rest of the network by gossip, hop by hop, and is visible to everyone on the way; one sent to a block engine in the region of the next block producer skips the gossip altogether. On a chain whose leaders change every few hundred milliseconds, which region to send to is a scheduling question.
- **Sections.** Running and peering nodes; Transaction propagation networks and private relays; Block-builder and block-engine endpoints by region; Validator proximity and the leader schedule; Hosted node providers.
- **Defines.** gossip protocol, transaction propagation network, leader schedule, block engine, hosted node provider.
- **Uses (defined earlier).** full node (B3.26), archive node (B3.26), RPC endpoint (B3.26), mempool (B3.14), validator (B3.14), block builder (B3.22), MEV relay (B3.22), proposer--builder separation (B3.22), transaction bundle (B3.22), private order flow (B3.22), searcher (B3.22), finality (B3.14), rate limit (B3.15), geodesic distance (ch10), latency floor (ch10), group index (ch10), route factor (ch10).
- **Tutorial.** A labelled simulation with parameters from cited measurements: gossip on a random peer graph whose nodes sit at geomap sites, the time for a transaction to reach half and nine-tenths of the nodes, and the effect of peering directly with builders; then an endpoint chooser that reads a leader schedule and sends to the block-engine region nearest the next leader. End state: propagation curves and the landing-rate gain of the leader-aware chooser.
- **Build.** `firm.chainnet`: a peer-graph generator with geographic latencies, gossip propagation (flooding and square-root fan-out), a leader-schedule-aware endpoint chooser over published regional endpoints (dated data); Python. Consumed by chapter 29.
- **Weekend problem.** The leader is in Frankfurt -- named result: the propagation time to half and nine-tenths of a network, and the gain in timely arrival from sending to the block engine nearest the next leader against a fixed region.
- **Facts to verify.** Ethereum consensus specifications: 12-second slots; Solana documentation: leader schedule, slots of about 400 ms, consecutive slots per leader; Jito Labs documentation: mainnet block-engine regions and endpoints (dated); Flashbots Protect / MEV-Share documentation (dated); a transaction propagation network's documentation (e.g., bloXroute) (dated); a measurement paper on Ethereum or Bitcoin propagation delay (e.g., Decker and Wattenhofer 2013); hosted node providers' documented rate limits (dated).
- **Data.** Published endpoint lists (dated rows); simulations labelled.
