\chapter{Reading, Debugging and Software Design}\label{ch:iv3:reading-debugging-and-software-design}

\begin{ivtrains}
Reading a short listing and saying what it really does, then naming the bug, the tool that would prove it and the smallest fix. The first questions are the ones you are expected to spot in seconds. The later ones ask how you would hunt a fault you cannot see, how you would test a piece of trading code, and how you would shape it so the same logic runs live and in a backtest. A few stems are in Java or C\#, because banks ask them there.
\end{ivtrains}
