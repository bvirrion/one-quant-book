\section*{Chapter \ref{ch:pl:columnar-formats} --- Columnar Formats}

\begin{solution}{exo:pl:columnar-formats:1}
Row-oriented: every row is read whole, $5 \times 8 \times 10^6 = 40$~MB. Columnar: one column, $8 \times 10^6 = 8$~MB.
\end{solution}

\begin{solution}{exo:pl:columnar-formats:2}
Bitmap: 1\,000 bits, 125 bytes. Offsets: $1\,001 \times 4 = 4\,004$ bytes. Data: 49 bytes. In all 4\,178 bytes; the nulls cost
their bit and an offset each, no data.
\end{solution}

\begin{solution}{exo:pl:columnar-formats:3}
Four values need 2 bits each: $50\,000 \times 2 / 8 = 12\,500$ bytes of indices. \texttt{firm.colfile} adds a 9-byte header
(count, dictionary size, bit width) and the dictionary itself stored plain, 40 bytes (a count, five 4-byte offsets and 16
characters): 12\,549.
\end{solution}

\begin{solution}{exo:pl:columnar-formats:4}
In capture order consecutive quotes of all fifty symbols are about half a second apart, $4.7\times10^8$~ns, so each delta needs
about 29 bits and each block's width is set by its largest delta: 32.2 bits a value measured. Sorted by symbol, consecutive rows
are quotes of one symbol, about 23 seconds apart, and each symbol's run starts with a jump back in time: 44.9 bits a value. \omterm{def:pl:columnar-formats:encodings}{Delta
encoding} pays for the size of the steps, and sorting by another key makes the time steps larger.
\end{solution}

\begin{solution}{exo:pl:columnar-formats:5}
Every \omterm{def:pl:columnar-formats:rowgroup}{row group} of a time-ordered file holds quotes of all fifty symbols, so its symbol \omterm{def:pl:columnar-formats:pushdown}{zone map} is S000 to S049 and no group can
be skipped. The reader still applies projection: it reads only the symbol column (to filter) and the bid and ask, 28\% of the
file, to return 2\% of the rows.
\end{solution}

\begin{solution}{exo:pl:columnar-formats:6}
To the right, large groups make each \omterm{def:pl:columnar-formats:pushdown}{zone map} cover a long stretch of time, so more of each read group is outside the hour
(6.00~MB at 524\,288 rows in time order). To the left, the footer, which every query reads before anything else, grows with the
number of groups and columns: 444~kB at 2\,048 rows against 115~kB at 8\,192. The minimum is where coarse \omterm{def:pl:columnar-formats:pushdown}{zone maps} stop costing
more than metadata.
\end{solution}

\begin{solution}{exo:pl:columnar-formats:7}
The file has 123 \omterm{def:pl:columnar-formats:rowgroup}{row groups}; the \omterm{def:pl:columnar-formats:pushdown}{zone maps} on the symbol and the timestamp leave two that may match, and the reader decodes only
those two groups' chunks of the four columns. It returns 153 rows, equal to pyarrow's answer on the same data.
\end{solution}

\begin{solution}{exo:pl:columnar-formats:8}
Statistics on a column prune only if its values are narrow within each \omterm{def:pl:columnar-formats:rowgroup}{row group}. In a time-sorted file every group contains every
symbol, so the symbol's \omterm{def:pl:columnar-formats:pushdown}{zone maps} cover everything and a one-symbol query reads the projected columns of every group (28\% of the
chapter's file for a query returning 2\% of the rows). Sort by symbol inside each date partition, or keep a second copy.
\end{solution}

\begin{solution}{pb:pl:columnar-formats:1}
\begin{enumerate}
\item All of it, since every row is read whole; a \omterm{def:pl:columnar-formats:layouts}{columnar layout} would read $2/9 = 22\%$.
\item A \omterm{def:pl:columnar-formats:validity}{validity bitmap}, an offsets buffer of $n+1$ integers and a data buffer.
\item It is one bit of the \omterm{def:pl:columnar-formats:validity}{validity bitmap}; the value itself takes no space in the data buffer.
\item Dictionary (13 bytes), dictionary (37\,917), delta (201\,085), dictionary (99\,097).
\item Sorted, the day's 50\,000 symbols are 50 runs, stored as 50 values and 50 lengths.
\item The minimum and maximum of a column in the group; it allows the reader to skip the group when some condition of the filter
is false for every value in that range.
\item No: a matching row lies inside its group's range for every filtered column, so its group is never skipped.
\item 86.0\% at 32\,768 rows a group; only projection saves anything, by leaving out the columns the query does not name.
\item 3.30\% for one symbol and 3.13\% for all symbols.
\item 86.1\%: each group holds a few symbols over the whole month, so every group's time range contains the hour.
\item 6.00~MB.
\item 0.39~MB.
\item The footer, read first, lists every chunk of 489 groups.
\item 3.9 times (444 against 115~kB).
\item 8\,192 on this data, from the measurement; on real data the same measurement with the real query mix.
\item \textbf{Named result.} With 8\,192-row groups, the one-symbol, one-hour query reads 87.2\% of the shuffled file (17.0 of
19.5~MB), 2.65\% in time order (0.39~MB) and 2.79\% sorted by symbol then time (0.36~MB); smaller and larger groups both cost
more (0.64~MB at 2\,048 rows, 6.00~MB at 524\,288 in time order).
\item Time order serves the one-hour queries, symbol order the one-symbol queries; a shuffled file serves neither.
\item Partition by date, sort each day by symbol then time, choose the row-group size by measurement; keep a time-ordered copy if
cross-sections matter as much.
\item The real query mix, the real distribution of symbols and quote rates (a few symbols dominate), and the bytes read, not the
wall time alone.
\item How narrow the \omterm{def:pl:columnar-formats:pushdown}{zone maps} of its filter columns are in the file's order, and how many columns it projects.
\end{enumerate}
\end{solution}

\begin{solution}{iq:pl:columnar-formats:1}
Research reads a few fields of many records, and columns of one type compress well and vectorise; a columnar file reads only the
fields and \omterm{def:pl:columnar-formats:rowgroup}{row groups} needed. A row format is better for writing records as they arrive and for reading whole records one at a
time: the intraday capture, the order state of one order.
\iqlookfor{Reads of few fields over many rows; appends and point reads favour rows.}
\end{solution}

\begin{solution}{iq:pl:columnar-formats:2}
Evaluating the filter against each \omterm{def:pl:columnar-formats:rowgroup}{row group}'s (or page's) minimum and maximum before reading, and skipping those that cannot
match. It only helps if the file is sorted (or partitioned) so that the filtered columns have narrow ranges per group.
\iqlookfor{\omterm{def:pl:columnar-formats:pushdown}{Zone maps}; sort order decides.}
\end{solution}

\begin{solution}{iq:pl:columnar-formats:3}
Timestamp: \omterm{def:pl:columnar-formats:encodings}{delta encoding}, since it increases in small steps. Symbol: dictionary (few distinct values), or run-length once sorted
by symbol. Price: dictionary if few distinct prices in a chunk, otherwise deltas, since prices move by ticks.
\iqlookfor{Encoding matched to the column's structure, and dependence on sort order.}
\end{solution}

\begin{solution}{iq:pl:columnar-formats:4}
A \omterm{def:pl:columnar-formats:validity}{validity bitmap} with one bit a value, set when present; a column without nulls may omit it. A null costs one bit (and, for
variable-width columns, an offset), never a sentinel.
\iqlookfor{Bitmap, not sentinel; bit order LSB-first as a detail.}
\end{solution}

\begin{solution}{iq:pl:columnar-formats:5}
Measure bytes read, \omterm{def:pl:columnar-formats:rowgroup}{row groups} read and columns read per query (a counting file, the reader's statistics), against rows
returned. If the reads are far above the result, check the sort order against the filters, the row-group size, and whether
statistics are written. Then change the layout (partition by date, sort by the main filter, tune the group size) and re-measure.
\iqlookfor{Bytes read against rows returned, then layout, measured again.}
\end{solution}

\begin{solution}{iq:pl:columnar-formats:6}
Partition by date; within each day sort by symbol then time, with \omterm{def:pl:columnar-formats:rowgroup}{row groups} sized by measurement (thousands of rows) and
statistics on symbol and time; dictionary-encode symbols and conditions, delta-encode timestamps. Long single-symbol histories
read one small range per day; cross-sections of a time window read the day's partition, projected. If cross-sections are
frequent and large, add a time-sorted copy.
\iqlookfor{\omterm{def:pl:capturing-and-storing-tick-data:partition}{Partitioning} plus sort order plus the admission that one order cannot serve both.}
\end{solution}
