\section*{Chapter \ref{ch:ml:experiment-tracking-and-reproducibility} --- Experiment Tracking and Reproducibility}

\begin{solution}{exo:ml:experiment-tracking-and-reproducibility:1}
Parameters (a default changes between library versions), seed (the sample of rows and columns each tree sees), data snapshot
(a vendor revision), code version (a feature's definition), environment (library versions, thread counts, hardware changing the
order of floating-point sums).
\end{solution}

\begin{solution}{exo:ml:experiment-tracking-and-reproducibility:2}
A hash of the content identifies the run by what it is: two identical records get one identifier, a record cannot be changed
without changing its identifier, and nothing depends on when or where it was written, so the tracker itself is reproducible.
\end{solution}

\begin{solution}{exo:ml:experiment-tracking-and-reproducibility:3}
The deflated Sharpe ratio is the probability that the champion's true Sharpe ratio exceeds the best that 200 skill-less trials
would be expected to show: 0.15, weak evidence. The probabilistic Sharpe ratio compares it with zero, as if it were the only
trial: 0.96. The difference is the price of the search.
\end{solution}

\begin{solution}{exo:ml:experiment-tracking-and-reproducibility:4}
The formula assumes 200 independent trials; the runs share data and differ in a few parameters, so their validation returns are
strongly correlated and the effective number of independent trials is much smaller. The expected maximum of fewer trials is
lower, and the deflated Sharpe ratio higher; the effective number can be estimated from the runs' correlations.
\end{solution}

\begin{solution}{exo:ml:experiment-tracking-and-reproducibility:5}
Each entry includes the previous entry's hash, and its own hash covers its content: changing or deleting a line changes its hash
and breaks the link of every later line. It does not stop someone from rewriting the whole chain from the edited line onwards; for
that the latest hash must be anchored somewhere the editor cannot reach (a separate system, a signed daily digest).
\end{solution}

\begin{solution}{exo:ml:experiment-tracking-and-reproducibility:6}
Weights let you run the model, not rebuild it: without the data snapshot, code, parameters and seed you cannot retrain it, audit
how it was chosen, or retrain a corrected version that differs only in the correction. In the chapter every missing field changed
the rebuilt model's test Sharpe ratio by 0.44 to 1.28.
\end{solution}

\begin{solution}{exo:ml:experiment-tracking-and-reproducibility:7}
Ten seeds give test Sharpe ratios from $-0.20$ to 2.88, mean 1.03 and standard deviation 0.94. The champion's configuration is
unremarkable once its lucky seed is averaged out: its test Sharpe ratio of 0.91 is near the mean, and the spread is as large as
the mean.
\end{solution}

\begin{solution}{exo:ml:experiment-tracking-and-reproducibility:8}
For each weekly version: the \omterm{def:ml:experiment-tracking-and-reproducibility:tracker}{run record} (data snapshot, code version, parameters, seed, metrics), who triggered the retrain (the
scheduler, under whose authority), who approved promotion and on what evidence, the nature of the change (new data only, or new
code or parameters), the times of registration, promotion and retirement; the trail anchored and retained for the period the
rules require.
\end{solution}

\begin{solution}{pb:ml:experiment-tracking-and-reproducibility:1}
\textbf{Part I.}
\begin{enumerate}
\item Parameters, seed, data snapshot, code version, environment, metrics, artefact hash and timestamp; the identifier is the
record's hash.
\item From $-3.16$ to 2.22, median $-0.83$; the champion's validation 2.22 and test 0.91.
\item 0.96 and 0.15.
\item 3.58, above the champion's 2.22: the champion is not distinguishable from the luck of 200 independent tries (the benchmark
is conservative for correlated runs).
\end{enumerate}
\textbf{Part II.}
\begin{enumerate}[resume]
\item The vendor revised 1\% of returns (snapshot 2026-03), and the feature clipping moved from 3 to 2.5 standard deviations (v2).
\item From the registry's stage histories, as of 10 March 08:00: version 1, promoted on 2 March.
\item Registration and promotion with times and reasons, each entry hash-linked to the previous; editing a line breaks the chain.
\item Records of every material change to algorithmic trading software (when, by whom, approved by whom, what); order records of
high-frequency traders kept five years.
\end{enumerate}
\textbf{Part III.}
\begin{enumerate}[resume]
\item The rebuilt model's dump has the stored artefact's content hash: bit for bit the same model.
\item Every missing field breaks reproduction: default parameters $-1.28$, seed $+0.85$, latest data $-1.25$, current code
$-0.44$ in test Sharpe ratio.
\item That seed noise alone moves the result by as much as the choice of configuration.
\item Across library versions, thread counts or hardware, where floating-point order changes; there the standard is the same
metrics within the seed spread.
\end{enumerate}
\textbf{Part IV.}
\begin{enumerate}[resume]
\item \emph{Reproduce the March model.} Two hundred runs stand behind the champion, whose validation Sharpe ratio of 2.22 has a
deflated Sharpe ratio of 0.15; reproduction from the registry is exact, and it fails with any one of parameters, seed, data
snapshot or code version missing.
\item Not on this evidence: ask for the seed spread, the effective number of trials, and a longer validation.
\item Query the registry as of the date, follow the lineage to the run, rebuild it, and list all 200 trials from the tracker:
minutes, not weeks.
\item Retention and immutability of records and artefacts for the period, and anchoring of the \omterm{def:ml:experiment-tracking-and-reproducibility:registry}{audit trail}.
\item As a lower bound; the true count is higher, and the deflated Sharpe ratio is an upper bound.
\item Each retrain as a version with its snapshot, an automatic promotion rule recorded as the approver, and alerts when the
rule is overridden.
\item A person other than the model's author, under the firm's model-risk \omterm{def:ml:reinforcement-learning-foundations:mdp}{policy} (Book~6, chapter~26).
\item The run's full record and the same software.
\end{enumerate}
\end{solution}

\begin{solution}{iq:ml:experiment-tracking-and-reproducibility:1}
Parameters, seeds, data and code versions, environment, metrics and artefacts, for every run. Failed runs count as trials: without
them the multiple-testing correction is impossible and the chosen result looks better than it is.
\iqlookfor{the fields, and failed runs as trials.}
\end{solution}

\begin{solution}{iq:ml:experiment-tracking-and-reproducibility:2}
Fix and record seeds, use deterministic algorithms and single-threaded or fixed-order reductions, pin library versions, version
data and code, and verify by rebuilding and comparing content hashes.
\iqlookfor{determinism settings, pinned versions, and a hash comparison.}
\end{solution}

\begin{solution}{iq:ml:experiment-tracking-and-reproducibility:3}
The best of many trials is biased upwards; the deflated Sharpe ratio compares it with the expected maximum of that many null
trials, so the count (and the trials' correlation) decides how impressive a Sharpe ratio is.
\iqlookfor{selection bias and the deflated Sharpe ratio.}
\end{solution}

\begin{solution}{iq:ml:experiment-tracking-and-reproducibility:4}
Name, version, stage (candidate, production, retired), lineage (run, data, code), metrics, owner and approver, stage history with
reasons, links to the \omterm{def:ml:interpretability-and-model-governance:card}{model card} and validation report, and an append-only \omterm{def:ml:experiment-tracking-and-reproducibility:registry}{audit trail} of changes.
\iqlookfor{stages, lineage, approvals and history.}
\end{solution}

\begin{solution}{iq:ml:experiment-tracking-and-reproducibility:5}
Because the same name comes to mean different data; corrections create new immutable snapshots (content-hashed or dated) and runs
record which they used, so old results stay reproducible and new ones can be compared.
\iqlookfor{immutability and snapshot identifiers.}
\end{solution}

\begin{solution}{iq:ml:experiment-tracking-and-reproducibility:6}
Start from the registry's lineage: is the \omterm{def:ml:experiment-tracking-and-reproducibility:tracker}{run record} complete, is the data snapshot still available and unchanged (hash), the
code version checked out, the environment the same; rebuild and compare hashes; diff intermediate outputs stage by stage (Book~7's
pipeline manifests) to find where they diverge.
\iqlookfor{a systematic walk from lineage to the first diverging stage.}
\end{solution}
